## 候选项逐一裁决

### ① render 级窗口化 fit（fit 移到可见 slice，P1-① 契约局部重构）——**不实施**

- **前提**：基准仍偏紧才做。实测：稳态 flush 9.4–10.6µs（余量 ~100×），render 单帧 < 16ms 护栏通过。
- **成本**：破坏 P1-① 契约（超宽行裁剪/overlay 边框回归风险），需三套 byte-identical 测试 + 超宽行/overlay 回归测试兜底，改造成本高。
- **收益**：fit 已增量化为 O(Δ)（fitMemo 逐行复用 + 结构共享），全量 fit 只在宽度/主题切换时发生（冷路径）；render 路径本身已是可见切片（P2-③ 结构共享，render() 直接 slice 稳定 lines 数组，零每帧宽度税）。
- **裁决**：窗口化 fit 的收益（每帧只 fit 可见行）在当前 O(Δ) 增量下无剩余热点可消除；契约破坏风险 > 收益。**不实施**，理由：前提不成立 + 成本收益比倒挂。

### ② B-4 块级可见性掩码（四个子系统适配 + 原子切换）——**不实施**

- **前提**：toggle 需 O(1) 时才考虑（高成本独立里程碑）。
- **实测**：toggle 首帧 20–31ms（median，N6 护栏 < 50ms 通过，~2× 余量）——已从 N 路并行全量 refetch + 全量重建（225–290ms）降到本地重建 + fitMemo 复用（零 RPC）。
- **成本**：重写四个子系统（渲染/构建/滚动/缓存）+ 原子切换（opts 维度删除与掩码上线同步防中间态双重渲染）——方案明示"成本被原报告低估"。
- **收益**：仅把 toggle 从 ~25ms 降到 O(1)——当前 25ms 已远低于用户可感知阈值（16ms 帧预算边界，且为一次性操作非每帧），收益不成立；且其"与折叠互补"的旧理由已随折叠否决失效。
- **裁决**：**不实施**，理由：前提（toggle 需 O(1)）不成立 + 高成本低收益。

### ③ 节流微调（思考场景 flush 下限 150–250ms）——**不实施**

- **前提**：基准显示峰值仍超阈值才做，且人眼纹理无感。
- **实测**：flush 同步块 9.4–10.6µs（远低于任何可感知阈值）；流式 flush 已有**自适应退避**（`nextStreamFlushDelay`：构建耗时 > 当前间隔/2 → 翻倍退避至上限，构建 < 间隔/8 → 减半恢复）——思考流持续增长场景的节流已由该机制动态覆盖，无需硬编码下限。
- **成本**：引入固定下限会降低新消息到达的显示延迟（思考场景 flush 从事件驱动变节流），与人眼实时性目标相悖。
- **裁决**：**不实施**，理由：前提不成立 + 既有自适应退避已覆盖场景 + 硬下限有害。
