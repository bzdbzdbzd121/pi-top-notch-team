# ADR-0008: 团队定义云同步 —— git 私有仓库为后端、不自动合并、产物离开 `teams/`

## 状态

已接受（实现已交付：阶段 1–4；本文记录不可逆的关键决策）

## 背景

团队定义（`teams/*.yaml`）此前只存在于单机磁盘：换一台机器就要重新创建，误删只能靠人肉回忆。需求（D5–D25）要求「多机一致 + 可云备份」，同时明确：**不自动合并**、冲突由人判断语义、凭据不落在插件里、机器级配置独立于会话级设置。

方案形成期用真实 git 探针核查了数十个候选做法（详见方案 §7.H 的 25 条处置表），其中若干主张被实测证伪。本 ADR 记录最终落地的六个关键决策与一条「允许的中间态」——它们都是**高逆向成本**或**外人会意外**的选择。

## 决定

### 1. 用 git 私有仓库做后端，`teams/` 目录本身即工作区

- 远端是**用户自己创建**的私有仓库（插件不代建）；`teams/` 直接被 `git init` 成仓库（`git --git-dir teams/.git`），不另建镜像目录。
- 只借用 git 的**对象库、三方基准（merge-base）、传输与历史**；**不使用它的合并结果**（D19）。冲突判定与落盘策略全部自写（文件级三方比较）。
- 否决的替代：自研备份格式（失去历史/找回能力）、把仓库放到 `teams/.sync/` 再镜像（两处状态、易错位）。

**后果**：`teams/` 变成仓库后不能同时被外层仓库跟踪（dotfiles 场景会在启用前警告）；被删除的团队可从 git 历史找回。

### 2. 提交树以「云端树」为基（`read-tree` 云端 → 精确路径增删）

- 构造提交时先 `git read-tree <云端的 commit>`，再对变更路径 `git add` / `git update-index --force-remove`，最后 `git write-tree` + `git commit-tree`（**双父**：本地 tip 与云端 tip）。
- 实测教训：若只把本机的 `*.yaml` 暂存进空树，云端独有的团队与 `README` 等非团队文件会在推送时被**静默删除**。
- 全程不执行 `merge`：无共同祖先时 `merge -s ours` 会因 unrelated histories 直接失败；加 `--allow-unrelated-histories` 后结果树等于本地树，同样会删掉云端独有文件。首次接入的正确做法是「远端 tip 直接作为父提交」。

**后果**：删除动作必须显式表达（删除路径进删除集合），否则「云端有、本机没有」会被当成新增下载——这正是真值表 #9/#10 的意义。

### 3. 不自动合并；冲突逐个决策，被放弃的一侧留档

- 冲突分类见真值表（两边都改 / 两边新增同名 → 三选项；本机删+云端改、本机改+云端删 → 各两选项）。
- 决策结果：保留本地 / 采用远端 / 两边都留。「两边都留」= 本机版本继续作为该团队，云端版本**导入为一个新团队**（唯一名、内部 `name` 同步改写、过校验、随同步传播）。
- 被放弃的一侧（本机或云端版本）写入 `<rootDir>/sync-conflicts/`，与 `teams/` 物理隔离。

**后果**：冲突决策必须给出可看的差异（TUI 内置可滚动差异视图；RPC 降级为两侧大小/修改时间 + 人工命令），否则语义判断的收益落空。

### 4. 冲突产物不放 `teams/`（否决 `<名字>.remote.yaml`）

- `<名字>.remote` 本身是**合法团队名**（团队名只要求非空字符串），生成 `X.remote.yaml` 可能直接覆盖真实团队。
- 插件内部规则是「文件名 = 团队标识，写入用 YAML 内部 `name`」：`/team edit X.remote` 会把内容写进 `X.yaml`，**静默覆盖真正的团队 X**。
- 因此归档放在 `<rootDir>/sync-conflicts/`（不参与列表、不参与同步、不污染云端）；「两边都留」走改名新团队。

**后果**：归档有了独立的命名与存活规则（阶段 2–4 逐步收紧为「路径安全化 + 原路径短哈希 + 时间戳」，同一秒不同路径也绝不撞名；覆盖前留档；写失败即中止同步）。

### 5. 配置放独立文件 `sync.yaml`（否决塞进 `settings.yaml`）

- 远端地址与开关是**机器级**配置；`settings.yaml` 处在「临时设置（per-session overlay）+ `/team resume` 快照恢复」两套机制之下。
- 放进去会出现「仅当前会话生效的仓库地址」这类无意义状态，或 resume 时把旧地址恢复成生效值；还必须登记快照字段白名单，漏登记的失败模式是**静默丢失**（该设置系统已多次踩到）。
- 因此 `sync.yaml` 独立存在，且**不进**临时设置/快照机制（结构性排除）。

**后果**：`/team setting` 里的「云同步（机器级）」入口恒写 `sync.yaml`，不参与作用域分流。

### 6. 启动提醒的边界：只报云端更新，且非 TUI 静默降级

- 启动时**进程级一次**检测（latch；`reason === "reload"` 显式跳过）：`ls-remote` + `fetch --no-write-fetch-head` + 图关系比较（`rev-list --left-right --count`），只报「云端有 N 个提交尚未同步」。
- **不兼报本机未备份改动**（用户已确认保持 D13）：本机未备份情况只在 `/team sync status` 显示；README 明确「备份强度 = 执行同步的频率」。
- 失败分类：暂态（网络/超时/锁）与未知 → 静默；持久缺陷（git 未装、认证、仓库不存在、地址不一致）→ 恰好一次通知 + 修法；非 TUI（rpc/json/print）→ 静默降级（零网络、零通知、不抛错）。
- 处理器**同步返回**，网络工作放在自捕获的游离 promise 中并设硬超时——上游在 pi 0.83.0（声明的最低版本）里确实 `await` `session_start` 的处理链：**启动路径 `agent-session.js:1761`**（`await this._extensionRunner.emit(this._sessionStartEvent)`，默认 `reason: "startup"`，见同文件 `:151`）；`reload` 分支另在 `:2070`（`emit({ type: "session_start", reason: "reload" })`）。处理器内 await 网络会推迟启动。

**后果**：启动不阻塞、失败不打扰；代价是「长期不同步的机器既不上传也没有提醒」。

### 允许的唯一中间态

**「本地已提交但推送失败」是设计允许的唯一中间态**，结果摘要明确标注（`（本地已提交，尚未推送）` + 推送失败原因与修法），重跑即收敛（推送成功前不产生第二次提交）。其余任何失败路径都必须回滚到「未做任何改动」：文件用内存回滚日志还原，留档一并清除，分支引用不动。

## 权衡与边界

- **备份强度 = 用户执行 `/team sync` 的频率**（不自动推送、不轮询）。这是明确接受的语义，不是缺陷。
- **非团队文件「云端为准」**：本机对 `teams/README.md` 之类文件的改动不上传，会被云端版本覆盖——**覆盖前留档**并在摘要里提示。
- **不支持多远端、多分支、多人协作**：所有冲突模型假设「两边都是你自己改的」；远端分支歧义时明确报错而不是猜。
- **平台范围**：Linux（git 2.53）已完成机制验证；Windows/macOS 按其行为做防御性设计（行尾过滤交给 git 语义、大小写不敏感名字归一、Windows 保留设备名规避、路径安全化）但**未实测**，README 明确标注。
- **凭据**：插件不保存 token；地址校验拒绝任何内嵌密码（`https://user:pass@…` 一律拒绝，`ssh://git@…` 允许，因为 `git` 不是秘密）。仓库是公开仓库时 `systemPrompt` 会外泄——首次配置文案强提示，不做自动检测（用户知情选择）。

## 后果

- 新增模块：`src/sync/{config,git-runner,lock,classify,plan,apply,decide,detect,command}.ts`、`src/ui/sync-diff-view.ts`；`/team sync`、`/team sync status` 两条命令；`/team setting` 顶层「云同步（机器级）」入口。
- 静态守卫：生产代码中除白名单（`src/sync/git-runner.ts`、`src/process/member-process.ts`、`src/setup/member-lifecycle.ts`、`src/tools/tl-tools.ts`）外禁止直接 `child_process`；同步模块不得调用裸 `loadSettings(`。
- 回归面：三方比较真值表 13 行、冲突四形态 × 各选项、归档命名唯一性、导入名唯一性（含远端/基准树已有名）、TOCTOU 中止、回滚、首次接入三类起点、删除传播、推送被拒后重跑收敛、备份恢复。
- 相关文档：`DESIGN.md` §32（基础设施与命令）、§33（同步全流程与失败语义）、`README.md`「云同步」一节（首次接入、恢复演练、找回命令、平台标注）。
